sesame-agent-tools

Give your Sesame agents a personal tool — host it yourself, teach it once.

Your Sesame agents (Maya, Miles, Charlie, Simone) can call a tool you host to answer things only your own data knows. You control the endpoint and the key; nobody shares anyone else's server. This page is the template — Use this template on GitHub, build your tools, and point the Sesame macOS client at your URL.

How it works

You ──ask──▶ Agent ──fetch(dir,key)──▶ your endpoint ──text──▶ Agent ──answer──▶ You (server-side, authorised by a rotating key)

While the custom tool is enabled, the app silently tells your agent — via the session's location-context field, never shown in chat — that a tool lives at your URL, and hands it a rotating access key. When you ask for something it can't answer, the agent fetches your-url?dir=<path>&depth=<1-3>&key=<key> and reads the reply back to you. Sesame's memory means you only have to explain the tool once.

The rotating key

key = HMAC_SHA256(secret, floor(unixtime / 300))   // first 10 hex chars, new every 5 min

Set the same shared secret in the app and in your endpoint. Your endpoint accepts the current or previous window, so a leaked key dies within ~10 minutes. Ready-made implementations: lib/keys.js, lib/keys.py.

Set it up

  1. Use this template → your own repo.
  2. Static context? Enable GitHub Pages and edit tool.txt. Real tools? Deploy worker/worker.js or run server/tree_server.py.
  3. Choose a long random shared secret; set it in your endpoint.
  4. In the app: Settings → Advanced → turn on Custom tool endpoint, paste your URL and the same secret.
  5. In a chat or call, tell the agent once what the tool does. It remembers.

Endpoint contract

GET  <base>/tool?dir=<path>&depth=<1-3>&key=<key>
     → verify key (current or previous 5-min window), else 403
     → return a plain-text directory tree (dir = folder under root; depth 1–3)
